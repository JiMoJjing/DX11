# DirectX11 짧은 학습 기록 - 프레임워크 제작

## 수강 범위

- 섹션: 4. 프레임워크 제작
- 제외: `Transform` 행렬 계산 내용

## 오늘 만든 것

- `Game.cpp`에 몰려 있던 DirectX11 코드를 엔진 클래스들로 분리했다.
- `Graphics` 클래스로 Device, SwapChain, RTV, Viewport 생성을 옮겼다.
- `Pipeline` 클래스로 IA, VS, RS, PS, OM 바인딩을 모았다.
- `GameObject`가 Geometry, Buffer, Shader, Texture, State를 들고 렌더링되도록 만들었다.
- Buffer, Shader, Texture, State 객체를 각각 래퍼 클래스로 만들었다.

## 핵심 흐름

```text
1. Game::Init()에서 Graphics, Pipeline, GameObject를 만든다.
2. Graphics가 Device, DeviceContext, SwapChain, RTV, Viewport를 준비한다.
3. GameObject가 Geometry, Buffer, Shader, Texture, State를 생성한다.
4. Game::Update()는 GameObject::Update()를 호출한다.
5. Game::Render()는 RenderBegin -> GameObject::Render -> RenderEnd 순서로 실행된다.
6. GameObject::Render()는 Pipeline에 리소스를 바인딩한다.
7. Pipeline이 DrawIndexed()를 호출한다.
```

## 핵심 코드

```cpp
void Game::Init(HWND hwnd)
{
    _graphics = make_shared<Graphics>(hwnd);
    _pipeline = make_shared<Pipeline>(_graphics->GetDeviceContext());
    _gameObject = make_shared<GameObject>(
        _graphics->GetDevice(),
        _graphics->GetDeviceContext()
    );
}
```

```cpp
void Game::Render()
{
    _graphics->RenderBegin();
    _gameObject->Render(_pipeline);
    _graphics->RenderEnd();
}
```

```cpp
PipelineInfo info;
info.inputLayout = _inputLayout;
info.vertexShader = _vertexShader;
info.pixelShader = _pixelShader;
info.rasterizerState = _rasterizerState;
info.blendState = _blendState;

pipeline->UpdatePipeline(info);
pipeline->SetVertexBuffer(_vertexBuffer);
pipeline->SetIndexBuffer(_indexBuffer);
pipeline->SetConstantBuffer(0, SS_VertexShader, _constantBuffer);
pipeline->SetTexture(0, SS_PixelShader, _texture);
pipeline->SetSamplerState(0, SS_PixelShader, _samplerState);
pipeline->DrawIndexed(_geometry->GetIndexCount(), 0, 0);
```

## 클래스별 역할

| 클래스 | 역할 |
| --- | --- |
| `Game` | 전체 실행 흐름 제어 |
| `Graphics` | Device, SwapChain, Render Target, Viewport 관리 |
| `Pipeline` | DirectX11 파이프라인 바인딩 담당 |
| `GameObject` | 렌더링에 필요한 리소스를 묶은 객체 |
| `Geometry<T>` | 정점과 인덱스 데이터 보관 |
| `GeometryHelper` | 사각형 같은 기본 도형 생성 |
| `VertexBuffer` | Vertex Buffer (`ID3D11Buffer`) 생성 |
| `IndexBuffer` | Index Buffer (`ID3D11Buffer`) 생성 |
| `InputLayout` | C++ 정점 구조와 HLSL 입력 연결 |
| `Shader` | HLSL 컴파일과 Shader Blob (`ID3DBlob`) 생성 |
| `VertexShader` | Vertex Shader (`ID3D11VertexShader`) 생성 |
| `PixelShader` | Pixel Shader (`ID3D11PixelShader`) 생성 |
| `ConstantBuffer<T>` | CPU 데이터를 GPU Constant Buffer로 복사 |
| `Texture` | 이미지 파일을 SRV (`ID3D11ShaderResourceView`)로 생성 |
| `RasterizerState` | RS 단계 상태 설정 |
| `SamplerState` | 텍스처 샘플링 방식 설정 |
| `BlendState` | OM 단계 색상 합성 방식 설정 |

## 렌더링 파이프라인에서 위치

- IA: `Geometry`, `VertexBuffer`, `IndexBuffer`, `InputLayout`을 사용한다.
- VS: `VertexShader`, `ConstantBuffer`를 사용한다.
- RS: `RasterizerState`를 사용한다.
- PS: `PixelShader`, `Texture`, `SamplerState`를 사용한다.
- OM: `Graphics`의 Render Target과 `BlendState`를 사용한다.

## 오늘 이해한 것

- `Game`은 이제 DirectX11 세부 API를 직접 많이 알 필요가 없다.
- `Graphics`는 화면에 그리기 위한 기본 장치들을 만든다.
- `Pipeline`은 이미 만들어진 리소스를 렌더링 파이프라인에 꽂는 역할이다.
- `GameObject`는 실제로 그려질 하나의 객체 역할을 한다.
- `Geometry`는 CPU 데이터이고, `VertexBuffer`와 `IndexBuffer`는 GPU Buffer다.
- `Texture`는 이미지 리소스이고, `SamplerState`는 이미지를 읽는 방식이다.
- `ShaderScope`를 쓰면 Constant Buffer, Texture, Sampler를 어느 Shader 단계에 바인딩할지 고를 수 있다.

## 헷갈린 부분

- `Graphics`와 `Pipeline` 둘 다 렌더링 관련이지만 역할이 다르다.
  - `Graphics`: Device, SwapChain, RTV 같은 기반 준비
  - `Pipeline`: IA, VS, RS, PS, OM 단계에 리소스 바인딩
- `Geometry`와 `VertexBuffer`는 다르다.
  - `Geometry`: CPU 쪽 정점/인덱스 배열
  - `VertexBuffer`: GPU가 읽는 Buffer
- `Shader Blob`은 Shader 생성뿐 아니라 Input Layout 생성에도 필요하다.
- `Texture`와 `SamplerState`는 같이 쓰이지만 같은 객체가 아니다.
