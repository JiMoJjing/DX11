# 2026-05-05 DirectX11 렌더링 흐름 복습

## 리뷰 주제

윈도우 창 생성 이후, DirectX11에서 한 프레임을 그리기 위해 필요한 초기화 단계와 매 프레임 렌더링 흐름을 복습했다.

이번 정리는 사용자가 직접 떠올린 순서를 기준으로, 각 단계가 DirectX11 렌더링 파이프라인에서 어디에 해당하는지 보완한 것이다.

## 내가 떠올린 흐름

### 초기화 단계

1. Device, DeviceContext, SwapChain 생성
2. SwapChain의 Back Buffer를 얻어서 RTV 생성
3. Viewport 설정 생성
4. 그릴 지오메트리 준비 후 Vertex Buffer 생성
5. Blob에 셰이더 파일을 담고, Blob으로 Vertex Shader 생성
6. Pixel Shader도 같은 방식으로 생성
7. `vsBlob`을 사용해서 Input Layout 생성

### 그리기 전 단계

8. Output Merger를 RTV에 연결
9. RTV 초기화
10. `RSSetViewports`로 Rasterizer Stage에 Viewport 설정

### 그리기 단계

11. Vertex Buffer 설정
12. Input Layout 설정
13. Primitive Topology 설정
14. 보통 이 근처에 Index Buffer 설정도 들어감
15. Vertex Shader 설정
16. Rasterizer Stage는 현재 별도 설정 없음
17. Pixel Shader 설정
18. Draw 호출

### 화면 출력 단계

19. `SwapChain->Present(1, 0);`

## 보완된 흐름

### 1. Device, DeviceContext, SwapChain 생성

Device (`ID3D11Device`)는 GPU 리소스를 생성하는 객체다.  
DeviceContext (`ID3D11DeviceContext`)는 렌더링 명령을 GPU 파이프라인에 전달하는 객체다.  
SwapChain (`IDXGISwapChain`)은 Back Buffer와 Front Buffer를 교체하면서 최종 결과를 화면에 보여주는 역할을 한다.

즉, 초기화의 출발점은 다음 세 가지다.

```cpp
ID3D11Device* device;
ID3D11DeviceContext* deviceContext;
IDXGISwapChain* swapChain;
```

### 2. Back Buffer에서 RTV 생성

SwapChain의 Back Buffer는 실제로 그림이 그려질 Texture (`ID3D11Texture2D`)다.  
이 Texture에 렌더링하려면 Render Target View (`ID3D11RenderTargetView`)가 필요하다.

```cpp
swapChain->GetBuffer(0, __uuidof(ID3D11Texture2D), (void**)&backBuffer);
device->CreateRenderTargetView(backBuffer, nullptr, &renderTargetView);
```

Render Target View는 "이 Texture를 렌더링 결과가 기록될 대상으로 사용하겠다"는 뷰라고 볼 수 있다.

### 3. Viewport 설정

Viewport (`D3D11_VIEWPORT`)는 렌더링 결과를 화면의 어느 영역에 매핑할지 정한다.

```cpp
D3D11_VIEWPORT viewport = {};
viewport.TopLeftX = 0.0f;
viewport.TopLeftY = 0.0f;
viewport.Width = width;
viewport.Height = height;
viewport.MinDepth = 0.0f;
viewport.MaxDepth = 1.0f;
```

Viewport는 나중에 Rasterizer Stage (`RS`)에 설정된다.

### 4. 지오메트리 준비

지금 단계에서는 직접 정점 배열을 만들어 Vertex Buffer (`ID3D11Buffer`)를 생성한다.

나중에 FBX, OBJ, glTF 같은 모델 파일을 읽게 되면, 파일 안에 있는 정점, 인덱스, 노멀, UV 같은 데이터를 읽어 Vertex Buffer와 Index Buffer (`ID3D11Buffer`)로 올리게 된다.

단, FBX 로딩은 DirectX11 자체 기능이 아니라 FBX SDK, Assimp 같은 외부 로더가 담당하는 영역에 가깝다.

### 5. Shader Blob으로 Vertex Shader 생성

Shader Blob (`ID3DBlob`)은 컴파일된 셰이더 바이트코드다.  
HLSL 파일을 컴파일하면 Blob이 나오고, 이 Blob을 사용해서 Vertex Shader (`ID3D11VertexShader`)를 생성한다.

```cpp
D3DCompileFromFile(..., &vsBlob, ...);
device->CreateVertexShader(
    vsBlob->GetBufferPointer(),
    vsBlob->GetBufferSize(),
    nullptr,
    &vertexShader
);
```

### 6. Pixel Shader 생성

Pixel Shader (`ID3D11PixelShader`)도 같은 방식으로 만든다.  
HLSL 파일을 컴파일해서 Pixel Shader용 Blob을 얻고, 그 Blob으로 Pixel Shader 객체를 생성한다.

```cpp
D3DCompileFromFile(..., &psBlob, ...);
device->CreatePixelShader(
    psBlob->GetBufferPointer(),
    psBlob->GetBufferSize(),
    nullptr,
    &pixelShader
);
```

### 7. `vsBlob`으로 Input Layout 생성

Input Layout (`ID3D11InputLayout`)은 Vertex Buffer의 데이터 구조와 Vertex Shader의 입력 구조를 연결한다.

예를 들어 Vertex Buffer에는 position, color가 들어 있고, Vertex Shader 입력도 `POSITION`, `COLOR`를 받는다면 이 둘의 형식을 맞춰주는 역할을 한다.

Input Layout을 만들 때 `vsBlob`이 필요한 이유는 Vertex Shader의 입력 시그니처를 확인해야 하기 때문이다.

```cpp
device->CreateInputLayout(
    layoutDesc,
    layoutCount,
    vsBlob->GetBufferPointer(),
    vsBlob->GetBufferSize(),
    &inputLayout
);
```

## 매 프레임 렌더링 흐름

### 8. Output Merger에 RTV 연결

Output Merger (`OM`) 단계에 Render Target View를 연결해야 Pixel Shader 결과가 Back Buffer에 기록된다.

```cpp
deviceContext->OMSetRenderTargets(1, &renderTargetView, nullptr);
```

현재는 Depth Buffer를 사용하지 않으므로 세 번째 인자는 `nullptr`이다.

### 9. RTV 초기화

`ClearRenderTargetView`는 Render Target View를 특정 색으로 지운다.

이 작업을 하지 않으면 이전 프레임의 내용이 남아 있을 수 있다. 특히 새로 그리는 도형이 화면 전체를 덮지 않으면 잔상처럼 보일 수 있다.

```cpp
float clearColor[4] = { 0.1f, 0.1f, 0.3f, 1.0f };
deviceContext->ClearRenderTargetView(renderTargetView, clearColor);
```

### 10. Rasterizer Stage에 Viewport 설정

`RSSetViewports`는 Rasterizer Stage (`RS`)에 Viewport를 설정한다.

"RS에 Viewport를 넘긴다"는 표현도 괜찮고, 더 정확히는 "Rasterizer Stage에 Viewport를 설정한다"라고 정리하면 좋다.

```cpp
deviceContext->RSSetViewports(1, &viewport);
```

### 11. Input Assembler 설정

Input Assembler (`IA`) 단계에서는 Vertex Buffer, Index Buffer, Input Layout, Primitive Topology를 설정한다.

```cpp
deviceContext->IASetVertexBuffers(0, 1, &vertexBuffer, &stride, &offset);
deviceContext->IASetInputLayout(inputLayout);
deviceContext->IASetPrimitiveTopology(D3D11_PRIMITIVE_TOPOLOGY_TRIANGLELIST);
```

Index Buffer가 있다면 이 근처에 함께 설정한다.

```cpp
deviceContext->IASetIndexBuffer(indexBuffer, DXGI_FORMAT_R32_UINT, 0);
```

삼각형 기반 렌더링에서는 보통 `D3D11_PRIMITIVE_TOPOLOGY_TRIANGLELIST`를 많이 사용한다.

### 12. Shader 설정

Vertex Shader와 Pixel Shader를 파이프라인에 설정한다.

```cpp
deviceContext->VSSetShader(vertexShader, nullptr, 0);
deviceContext->PSSetShader(pixelShader, nullptr, 0);
```

현재 Rasterizer State (`ID3D11RasterizerState`)를 따로 만들지 않았다면 기본 Rasterizer State가 사용된다.

나중에 다음과 같은 설정이 필요해지면 Rasterizer State를 직접 만들게 된다.

- Cull Mode
- Fill Mode
- Wireframe
- Front/Back Face 판정

### 13. Draw 호출

Index Buffer를 사용하지 않으면 `Draw`를 호출한다.

```cpp
deviceContext->Draw(vertexCount, 0);
```

Index Buffer를 사용하면 보통 `DrawIndexed`를 호출한다.

```cpp
deviceContext->DrawIndexed(indexCount, 0, 0);
```

Draw Call은 지금까지 파이프라인에 설정한 상태를 기준으로 실제 렌더링 명령을 실행하는 지점이다.

### 14. Present

마지막으로 SwapChain의 `Present`를 호출해서 Back Buffer의 내용을 화면에 표시한다.

```cpp
swapChain->Present(1, 0);
```

첫 번째 인자 `1`은 VSync를 기다리겠다는 의미다. 화면 찢어짐을 줄일 수 있어 학습 단계에서는 보통 이 값을 사용한다.

```cpp
swapChain->Present(1, 0); // VSync ON
swapChain->Present(0, 0); // VSync OFF, 더 빠르지만 tearing 가능
```

따라서 `Present(1, 0)`은 학습 단계에서 거의 기본값처럼 사용해도 괜찮지만, 항상 고정된 값은 아니다.

## 핵심 개념 메모

- Device (`ID3D11Device`)는 리소스 생성 담당이다.
- DeviceContext (`ID3D11DeviceContext`)는 렌더링 명령 실행 담당이다.
- SwapChain (`IDXGISwapChain`)은 최종 화면 출력 담당이다.
- Render Target View (`ID3D11RenderTargetView`)는 Back Buffer를 렌더링 대상으로 사용하기 위한 뷰다.
- Viewport (`D3D11_VIEWPORT`)는 렌더링 결과가 화면에 매핑되는 영역이다.
- Shader Blob (`ID3DBlob`)은 컴파일된 셰이더 바이트코드다.
- Input Layout (`ID3D11InputLayout`)은 Vertex Buffer 구조와 Vertex Shader 입력 구조를 연결한다.
- Input Assembler (`IA`)는 정점 데이터를 조립해서 파이프라인에 넘긴다.
- Rasterizer Stage (`RS`)는 정점으로 이루어진 도형을 픽셀 후보로 변환한다.
- Output Merger (`OM`)는 최종 픽셀 결과를 Render Target에 기록한다.

## 헷갈리기 쉬운 부분

### RTV를 Clear하는 이유

새 프레임을 그리기 전에 Back Buffer를 지우기 위해서다.

이전 프레임의 내용이 남아 있고, 새로 그린 도형이 화면 전체를 덮지 않으면 잔상이 보일 수 있다. 그래서 보통 매 프레임 `ClearRenderTargetView`를 호출한다.

### `vsBlob`으로 Input Layout을 만드는 이유

Input Layout은 Vertex Buffer의 데이터 형식과 Vertex Shader의 입력 형식을 맞춰야 한다.

따라서 Vertex Shader의 입력 시그니처를 확인할 수 있는 `vsBlob`이 필요하다.

### RS에 아무것도 설정하지 않았을 때

Rasterizer State를 직접 만들지 않았다면 기본 상태가 사용된다.

지금 단계에서는 괜찮지만, 나중에 컬링, 와이어프레임, 앞면/뒷면 판정 등을 제어하려면 Rasterizer State를 직접 설정하게 된다.

### `Present(1, 0)`은 고정인가?

학습 단계에서는 거의 기본값처럼 써도 된다.

하지만 첫 번째 인자는 VSync 여부와 관련이 있으므로, 성능 테스트나 프레임 제한을 다룰 때는 `Present(0, 0)` 같은 값도 사용하게 된다.

## 다음에 추가될 내용

3D 렌더링으로 넘어가면 Depth Buffer와 Depth Stencil View (`ID3D11DepthStencilView`)가 추가된다.

Depth Buffer는 앞에 있는 물체가 뒤에 있는 물체를 가리도록 깊이 판정을 하기 위해 필요하다. 지금처럼 단순 삼각형이나 2D에 가까운 예제에서는 없어도 되지만, 3D 모델을 그릴 때는 거의 필수다.

## 한 줄 정리

DirectX11의 기본 렌더링 흐름은 리소스를 만들고, 파이프라인에 필요한 상태를 설정한 뒤, `Draw`로 Back Buffer에 그리고, `Present`로 화면에 보여주는 과정이다.
